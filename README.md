# Godwin Ekanem — Software Engineering & AI Systems Portfolio

An evidence-led portfolio presenting software engineering, AI products, and intelligent automation work. Featured products link to proof-first case studies covering the experience, product flow, architecture, engineering decisions, reliability boundaries, result, and evidence.

## Stack

- Next.js 16.3.6 + React 19 + TypeScript
- Tailwind CSS 4
- Lucide React
- Vitest + Testing Library
- Vercel

## Local setup

```bash
corepack enable
pnpm install
pnpm dev
```

Optional: set `NEXT_PUBLIC_SITE_URL` to an explicit canonical production origin. On Vercel, the metadata falls back to Vercel's deployment hostname.

## Quality commands

```bash
pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

GitHub Actions runs the same test, lint, typecheck, and production-build gate for changes targeting `main`.

## Portfolio scope

The homepage leads with EchoRun, SignBridge, RelayDesk, ChatDocs, and LeadLens. A separate AI Automation progression connects Intelligent Invoice Processing, Operations Reporting & Decision Support, ProposalFlow, ContentLedger, LeadLens, and RelayDesk. The filterable project index keeps personal products and applied-ML work discoverable.

The résumé is published as a first-class `/resume` web route. Home and project-specific Open Graph imagery are generated by Next.js, so no binary social-card assets are required.

## Updating project content

Project case-study records live in `content/projects/*.json`; canonical display names, collections, proof media, facts, flow steps, and named actions are assembled in `content/projects.ts`. `lib/project-types.ts` documents the complete schema, while `lib/project-validation.ts` protects duplicate slugs, HTTPS links, media requirements, and facts.

- Use `media.kind: "image"` for an approved local screenshot stored under `public/projects/<slug>/`, with meaningful alt text.
- Use `media.kind: "loom"` with `status: "available"`, a Loom share ID, and a duration only after those values are confirmed.
- Keep `status: "pending-link"` when a Week 1–5 walkthrough exists but its Loom ID has not been supplied.
- Keep `status: "coming-soon"` for RelayDesk until its walkthrough is recorded.
- Personal products intentionally use no walkthrough UI.
- Add live and repository actions to `links`; public URLs must use HTTPS. Never add placeholder deployments or credentials.

Confirmed live applications are currently set for Operations Reporting & Decision Support and RelayDesk. Week 1–5 Loom share IDs, additional weekly live URLs, and approved product screenshots remain pending and render explicit fallbacks without breaking the build.

## Deployment

Import this repository into Vercel and deploy `main`. Then verify `/`, `/resume`, every `/work/<slug>` route, `/sitemap.xml`, `/robots.txt`, and `/opengraph-image` on the production URL.
