# Godwin Ekanem — AI Engineering & AI Automation Portfolio

A systems-led portfolio for software and AI work. The site presents AI Engineering and AI Automation as two responsibilities connected by the same engineering mindset: explicit state, controlled actions, inspectable evidence, deliberate failure paths, and interfaces built for real use.

The homepage is designed as a concise product-theatre journey rather than a catalogue. Four selected systems lead into dedicated AI Automation and AI Engineering collections, while each project has a proof-first case study covering product behaviour, system design, engineering decisions, recovery boundaries, outcomes, and evidence.

## Stack

- Next.js 16.3.6 + React 19 + TypeScript
- Tailwind CSS 4 and project CSS design layers
- Lucide React
- Vitest + Testing Library
- Vercel

No general-purpose motion dependency is required. Interactive motion uses React state, CSS transitions, pointer input, IntersectionObserver, and progressive browser APIs, with reduced-motion and coarse-pointer fallbacks.

## Local setup

```bash
corepack enable
pnpm install
pnpm dev
```

Optional: set `NEXT_PUBLIC_SITE_URL` to an explicit canonical production origin. On Vercel, metadata falls back to Vercel's deployment hostname.

## Portfolio structure

The homepage has four fully staged featured systems in this order: RelayDesk, EchoRun, LeadLens, and ChatDocs. It then opens into two exclusive collections:

- **AI Automation:** Intelligent Invoice Processing, Operations Reporting & Decision Support, ProposalFlow, ContentStudio, LeadLens, and RelayDesk.
- **AI Engineering:** EchoRun, ChatDocs, and SignBridge.

Featured status does not change collection ownership. The collection routes are `/work/ai-automation` and `/work/ai-engineering`, and the nine project case studies remain canonical at `/work/<slug>`.

The résumé is published as a PDF under `/resume/Ekanem_Godwin_Resume.pdf`. Home and project-specific Open Graph imagery are generated by Next.js, so no binary social-card assets are required.

## Design direction

The visual system is intentionally built around a signal/system motif rather than a generic developer aesthetic. The light neutral and teal foundation is interrupted by a dark selected-work theatre, then returns to editorial collection, engineering-practice, experience, and profile chapters before resolving into the dark contact panel. On large fine-pointer displays, a six-stage journey rail makes that progression visible; narrow, coarse-pointer, and reduced-motion environments keep the content direct and static.

Project case studies use a consistent seven-part narrative: system snapshot, product flow, system design, engineering decisions, failure and recovery, outcome, and verification. Architecture and flow diagrams are generated from project data rather than screenshot-like mock content.

## Updating project content

Project case-study records live in `content/projects/*.json`; canonical display names, collections, proof media, facts, flow steps, and named actions are assembled in `content/projects.ts`. `lib/project-types.ts` documents the complete schema, while `lib/project-validation.ts` protects duplicate slugs, HTTPS links, media requirements, and facts.

- Use `media.kind: "image"` for an approved local screenshot stored under `public/projects/<slug>/`, with meaningful alt text.
- Use `media.kind: "loom"` with `status: "available"`, a Loom share ID, and a duration only after those values are confirmed.
- Keep `status: "pending-link"` when a walkthrough exists but its public Loom ID has not been supplied.
- Keep `status: "coming-soon"` until a walkthrough is actually recorded.
- Personal products intentionally use no walkthrough UI.
- Add live and repository actions to `links`; public URLs must use HTTPS. Never add placeholder deployments, screenshots, credentials, or unsupported proof.

Approved product screenshots can be added later without changing the case-study structure; projects without authentic screenshots continue to use architecture visuals or explicit proof fallbacks.

## Deployment

Import this repository into Vercel and deploy `main`. Before production promotion, verify `/`, both collection routes, all nine `/work/<slug>` case studies, the résumé PDF, `/sitemap.xml`, `/robots.txt`, and `/opengraph-image` across desktop and mobile widths.
