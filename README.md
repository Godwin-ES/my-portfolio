# Godwin Ekanem — Software Engineering & AI Systems Portfolio

An evidence-led portfolio presenting a blend of AI Automation and AI Engineering. Four standout products lead into focused collections and proof-first case studies covering the experience, system architecture, engineering decisions, reliability boundaries, outcomes, and evidence.

## Stack

- Next.js 16.3.6 + React 19 + TypeScript
- Tailwind CSS 4
- Lucide React
- Vitest + Testing Library
- Vercel

## Local setup

```bash
corepack enable
pnpm install
pnpm dev
```

Optional: set `NEXT_PUBLIC_SITE_URL` to an explicit canonical production origin. On Vercel, the metadata falls back to Vercel's deployment hostname.

## Quality commands

```bash
pnpm test
pnpm lint
pnpm typecheck
pnpm build
```

GitHub Actions runs the same test, lint, typecheck, and production-build gate for changes targeting `main`.

## Portfolio scope

The homepage spotlights RelayDesk, EchoRun, LeadLens, and ChatDocs. The dedicated collections contain:

- AI Automation: Intelligent Invoice Processing, Operations Reporting & Decision Support, ProposalFlow, ContentStudio, LeadLens, and RelayDesk.
- AI Engineering: EchoRun, ChatDocs, and SignBridge.

The `/resume` route opens the published résumé PDF. Home and project-specific Open Graph imagery are generated by Next.js, so no binary social-card assets are required.

## Updating project content

Project case-study records live in `content/projects/*.json`; canonical display names, collections, proof media, facts, flow steps, and named actions are assembled in `content/projects.ts`. `lib/project-types.ts` documents the complete schema, while `lib/project-validation.ts` protects duplicate slugs, HTTPS links, media requirements, and facts.

- Use `media.kind: "image"` for an approved local screenshot stored under `public/projects/<slug>/`, with meaningful alt text.
- Use `media.kind: "loom"` with `status: "available"`, a Loom share ID, and a duration only after those values are confirmed.
- Keep `status: "pending-link"` when a Week 1–5 walkthrough exists but its Loom ID has not been supplied.
- Keep `status: "coming-soon"` for RelayDesk until its walkthrough is recorded.
- Personal products intentionally use no walkthrough UI.
- Add live and repository actions to `links`; public URLs must use HTTPS. Never add placeholder deployments or credentials.
- Curate three or four `architecture.previewNodeIds` for each visual preview. Every node should also have a concise functional `layer` for the full system map.

Confirmed live applications are currently set for EchoRun, ChatDocs, SignBridge, Operations Reporting & Decision Support, ProposalFlow, ContentStudio, LeadLens, and RelayDesk. Walkthroughs are published for Intelligent Invoice Processing, Operations Reporting & Decision Support, ProposalFlow, and LeadLens. ContentStudio’s link and RelayDesk’s recording remain pending and render explicit states without breaking the build.
